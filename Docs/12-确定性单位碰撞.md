# 12　确定性单位碰撞

[上一阶段](11-准备房间与连续多局.md) · [返回实现大纲](手动实现大纲.md) · [下一阶段](13-KayKit模型与动画.md)

适用：Unity 6000.3.23f1 / UnityMOBA_Manual。以下为后续手动实施教程，不表示已执行Unity运行验证。

## 本阶段要得到什么

活着的英雄、小兵和塔相互阻挡；遇到单个障碍尝试局部滑动；出生与复活不重叠；三端和回放仍逐帧一致。这是战斗规则变化，需要更新规则版本和验收记录。

前置条件：阶段11连续房间和阶段09回放可用。先关网络做几何/模拟测试，通过后再恢复多进程验证。

## 1. 先拆清两种 Collider

Unity Collider用于鼠标拾取；Core整数圆用于逻辑阻挡。两个系统可以体积不同，不能通过OnCollisionEnter、Rigidbody位置或Physics.OverlapSphere决定模拟结果。

新增文件按顺序为CollisionConfig、CollisionGeometry、CollisionMovement、SpawnPlacement、CollisionWorld；Presentation增加CollisionDebugView。

## 2. 创建配置并升级编码

创建CollisionConfig完整文件：


```csharp
// 完整文件：Assets/Moba/Runtime/Core/CollisionConfig.cs
using System;
using System.IO;

namespace Moba.Core
{
    public sealed class CollisionConfig
    {
        public const int StepLimit = 100, ContactMargin = 50, WaypointRadius = 1500;
        public readonly int HeroRadius, MinionRadius, TowerRadius;
        public CollisionConfig(int heroRadius = 550, int minionRadius = 460, int towerRadius = 1250)
        {
            if (heroRadius < 100 || heroRadius > 1500 || minionRadius < 100 || minionRadius > 1000 ||
                towerRadius < 100 || towerRadius > 2500) throw new ArgumentException("Invalid collision radii.");
            HeroRadius = heroRadius; MinionRadius = minionRadius; TowerRadius = towerRadius;
        }
        public int Radius(EntityKind kind) => kind == EntityKind.Tower ? TowerRadius : kind == EntityKind.Minion ? MinionRadius : HeroRadius;
        internal void Write(BinaryWriter w) { w.Write(HeroRadius); w.Write(MinionRadius); w.Write(TowerRadius); }
        internal static CollisionConfig Read(BinaryReader r) => new CollisionConfig(r.ReadInt32(), r.ReadInt32(), r.ReadInt32());
    }
}
```


在BattleConfig添加Collision字段、构造器可选参数`CollisionConfig collision=null`及默认赋值。构造器检查塔圆在地图内、地图宽高能容纳单位、恢复区能容纳英雄，以及小兵索敌距离不小于有效攻击距离。

在BattleConfigCodec.Write的Lane后追加Collision.Write；Read同位置读取CollisionConfig。把RulesVersion更新为manual-collision-1，更新配置/文件版本策略和握手签名。三端同时升级；旧无碰撞回放明确拒绝。

## 3. 先实现几何，不写移动

创建CollisionGeometry完整文件：


```csharp
// 完整文件：Assets/Moba/Runtime/Core/CollisionGeometry.cs
using System;

namespace Moba.Core
{
    public static class CollisionGeometry
    {
        public static bool Overlaps(Int2 a, Int2 b, int combinedRadius)
            => IntegerMath.DistanceSquared(a, b) < checked((long)combinedRadius * combinedRadius);

        public static bool Contains(BattleConfig c, Int2 p, int radius)
            => p.X >= c.MinX + radius && p.X <= c.MaxX - radius && p.Z >= c.MinZ + radius && p.Z <= c.MaxZ - radius;

        public static Int2 Clamp(BattleConfig c, Int2 p, int radius)
            => new Int2(Math.Max(c.MinX + radius, Math.Min(c.MaxX - radius, p.X)),
                Math.Max(c.MinZ + radius, Math.Min(c.MaxZ - radius, p.Z)));

        // The short-segment contract bounds all products, including the squared projection.
        public static bool SegmentEntersCircle(Int2 a, Int2 b, Int2 center, int radius)
        {
            if (Math.Abs((long)a.X) > 40000 || Math.Abs((long)b.X) > 40000 || Math.Abs((long)center.X) > 40000 ||
                Math.Abs((long)a.Z) > 10000 || Math.Abs((long)b.Z) > 10000 || Math.Abs((long)center.Z) > 10000 ||
                radius < 1 || radius > 5000) throw new ArgumentOutOfRangeException(nameof(radius), "Collision geometry bounds.");
            checked
            {
                long vx = (long)b.X - a.X, vz = (long)b.Z - a.Z;
                long length = vx * vx + vz * vz;
                if (length > CollisionConfig.StepLimit * CollisionConfig.StepLimit) throw new ArgumentException("Collision segment exceeds 100 mm.");
                long wx = (long)center.X - a.X, wz = (long)center.Z - a.Z, square = (long)radius * radius;
                long projection = wx * vx + wz * vz;
                if (length == 0 || projection <= 0) return wx * wx + wz * wz < square;
                if (projection >= length) return IntegerMath.DistanceSquared(b, center) < square;
                return (wx * wx + wz * wz) * length - projection * projection < square * length;
            }
        }
    }
}
```


约定：严格小于半径平方才算重叠；刚好相切不算重叠。Contains考虑整个圆，不只看中心。

SegmentEntersCircle检查的是整段路径，防止起终点都合法但中间穿过障碍。公式在投影落在线段内部时比较：

```text
(w·w) × (v·v) - (w·v)² < r² × (v·v)
```

短线段上限100与坐标范围约束是long乘积安全的一部分，不能删掉长度检查后拿整张地图长线段调用。所有运动候选都必须遵守这个契约。

先测试：零长线段、相切、端点在圆内、穿心、擦边、反向、非法长线段和地图角落。

## 4. 增加 MotionTrace 和诊断数据

在CollisionMovement.cs定义MotionTrace：容量11，Reset写初始点，Add写每个接受的子步端点。每帧最大速度1000、子步100，所以最多10步加起点。

EntityState增加：
```csharp
public MotionTrace Motion { get; } = new MotionTrace();
```

Motion是当前帧显示轨迹，不影响下一帧规则，不写进状态hash。CollisionDiagnostics记录PathChecks、SpawnChecks、Substeps、Slides、时间和分配；它同样不参加hash。

每帧执行任何移动前先对所有实体`Motion.Reset(Position)`。错过这一步会让显示沿上帧轨迹走。

## 5. 写短步移动与固定滑动候选

按 [CollisionMovement.Move](../../UnityMOBA/Assets/Moba/Runtime/Core/CollisionMovement.cs) 分三个方法职责实现：Move组织预算、Free检查路径、IntegerMath负责整数步长。

**移动伪代码：**

```text
budget = speed
while budget > 0 且未到目标：
    若追击已经进入有效攻击距离：停止
    q = min(100, budget); budget -= q
    direct = MoveTowards(start, goal, q)
    若Free(start,direct)：接受direct
    否则：
        检查目标是否落在当前阻挡圆内部
        目标不在阻挡圆内部时，按固定左右/角度顺序找滑动候选
        若仍无候选，二分尝试更短的直接步
    若位置没变化：停止本帧剩余移动
    写Position并追加Motion端点
```

滑动方向使用固定整数表Cos={946,724,392,0}、Sin={392,724,946,1024}，归一化后仍限制长度q。左右优先由EntityId奇偶固定，不使用Random或Time。

所有存活单位参与阻挡，不排除同队。Free先做宽阶段轴向范围排除，再用SegmentEntersCircle确认。塔没有移动预算。

二分缩短直接步最多7次即可覆盖1—99；选择顺序必须一致。不能枚举Dictionary的偶然顺序决定优先绕哪边。

## 6. 固定实体移动顺序

沿既有entities稳定顺序执行Movement。创建时初始ID顺序固定，小兵按队伍和序号添加；删除后保留剩余相对顺序。移动者可以看到本帧已经处理的单位新位置，这是明确的顺序规则。

不要一端按渲染物体顺序、一端按字典顺序。若改为排序执行，应三端一致并更新对应测试。

碰撞只阻挡/滑动，没有物理推挤，也不保证绕过整片拥堵。卡住时保留MoveTo意图，等障碍消失或玩家换目标。

## 7. 实现确定性 SpawnPlacement

按 [SpawnPlacement.cs](../../UnityMOBA/Assets/Moba/Runtime/Core/SpawnPlacement.cs) 建预计算候选：

1. 在出生点局部范围[-3000,3000]内按250网格枚举。
2. 过滤恢复区和地图边界，单位圆必须放得下。
3. 玩家优先偏移(0,-1000)，机器人(0,1000)，三类小兵优先(1500,(ordinal-1)×1000)。
4. 按距偏好点距离、固定X/Z顺序排序；红方按固定符号映射到世界。
5. TryFind遍历候选，与全部存活圆做严格重叠检查，取第一个合法点。

初态先把所有英雄视为未占位，再按固定ID逐个放置。初态没有合法位置则准备失败，不能强行重叠。

复活没有位置时保留死亡状态和原RespawnFrame，每帧重试。小兵没有位置时跳过该名额，不能提前增加NextEntityId造成无意义ID债务。

## 8. 接入 CombatWorld 与 LaneRules

在CollisionWorld.cs作为CombatWorld的partial增加：

- placement字段、Radius(entity)、EffectiveAttackRange、InAttackRange。
- InitializeCollision：构造placement、放置初态、初始化Motion、校验。
- ValidateCollisionState：逐个圆在地图内，任意两个活体不重叠。

移除阶段03的旧InAttackRange实现，避免重复定义。新的有效攻击距离：塔保留原TowerRange；其他单位取max(配置攻击距离, 双方半径之和+50)。

接线清单：

| 原位置 | 修改 |
| --- | --- |
| CombatWorld构造器最后 | InitializeCollision |
| Step命令验证后 | 校验碰撞状态；重置诊断；处理出生后重置Motion |
| AdvanceIntent的地面移动 | Clamp目标到容纳圆的边界；改用CollisionMovement.Move |
| 追击移动 | Move带attackTarget，到有效攻击距离即停 |
| ResolveDamage | 使用EffectiveAttackRange复核普攻距离 |
| LaneRules复活 | placement.TryFind失败则continue |
| LaneRules出兵 | TryFind成功才创建实体和递增ID |

MovementFixture测试的初态现在也会被安全出生重排。因此修改旧测试中硬编码-35000起点的期望，改成读取实际初态再计算；保留原整数算法测试不变。不要为让旧断言通过而关闭新碰撞。

## 9. 让表现沿合法路径走

阶段02EntityView只有from/to直线插值，滑过塔时可能视觉穿塔。改为复制Motion里的全部点，计算各段长度；给定alpha，沿累计长度找到所在段再插值。

```text
distance = totalPathLength × alpha
依次遍历相邻点段：
    distance大于本段长度 → 减去本段长度
    否则在本段起终点Lerp，结束
```

每帧Snapshot只处理一次；调用方传入World.Frame并避免同帧重复重置elapsed。死亡/初次创建/复活直接snap，不沿旧路径插值。

CollisionDebugView用LineRenderer画最新逻辑位置与Radius；模型插值位置可能落后不到一帧，调试圆不要反过来取模型位置。

## 10. 建立碰撞测试矩阵

| 组 | 必测情况 |
| --- | --- |
| 几何 | 相切、端点、穿越、角落、短线段上限 |
| 阻挡 | 同队/敌队英雄、小兵、塔；死亡单位不阻挡 |
| 滑动 | 单塔左右滑动、目标在塔内停外面、无加速 |
| 交叉 | 迎面、交叉、封闭包围、拥堵200帧 |
| 兵线 | 出生后经过己方塔、越过中点、攻击范围与体积兼容 |
| 出生 | 双英雄同时复活、出生区满、跳过小兵不提前耗ID |
| 协议 | 配置往返、新旧规则拒绝 |
| 系统 | 三端逐帧hash、连续房间与新回放 |

对照 [CollisionTests](../../UnityMOBA/Assets/Moba/Tests/EditMode/CollisionTests.cs)。旧测试直接摆单位时必须给彼此留足半径，否则新状态校验抛Overlap是正确结果。

性能测试用固定密集场景，分别记录验证、生成、移动耗时和分配；分配计数不可用标为未测得，不写0。
