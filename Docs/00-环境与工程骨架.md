适用：Unity 6000.3.23f1 / UnityMOBA_Manual。教程代码与操作用于后续手动实施；本次仅生成文档，不表示模板已经实现或运行通过。

## 本阶段要得到什么

打开模板后能够进入 Play Mode，代码放入正确的程序集，Test Runner 能发现后续测试。先把“项目能稳定编译”作为起点，再加入玩法。

前置条件：能打开 Unity Hub 和代码编辑器；项目目录为 `D:/Unity/UnityProjects/UnityMOBA_Manual`。本阶段不运行原项目的资源生成器。

## 1. 确认打开的是模板项目

1. 在 Unity Hub 添加上述目录，选择 **6000.3.23f1**。进入编辑器后，检查 Project 窗口中目前只有模板资源，尚无 Moba 业务目录。
2. 打开 `Assets/Scenes/SampleScene.unity`。在 Hierarchy 中确认 Main Camera、Directional Light、Global Volume。
3. 打开 Console，取消 Collapse 便于定位重复错误；先清空日志再进入 Play Mode，等待几秒后退出。记录已有错误，不删除资源来掩盖错误。
4. 在代码编辑器中打开模板项目的解决方案。确认文件完整路径属于 Manual，避免误改原 UnityMOBA。

**检查点**：能播放、能停止，Console 没有脚本编译错误。如果模板本身有错误，先解决，不进入阶段 01。

## 2. 核对包、输入与渲染设置

在 Window → Package Manager 中查看已安装包。以项目 manifest 为准：

| 包             | 当前版本 | 作用                                      |
| -------------- | -------- | ----------------------------------------- |
| Universal RP   | 17.3.0   | 材质、光照与渲染                          |
| Input System   | 1.20.0   | 鼠标与键盘                                |
| Test Framework | 1.6.0    | EditMode / PlayMode 测试                  |
| AI Navigation  | 2.0.14   | 模板已有，本路线不用 NavMesh 决定战斗移动 |

在 Edit → Project Settings → Player 中检查 Active Input Handling 为 Input System。修改后若提示重启，保存场景再重启。在 Graphics/Quality 中保留模板的 URP 引用，不复制原项目整个 ProjectSettings。

本次教程按本地锁定版本讲解，不需要为了学习先升级所有包。模板的 InputSystem_Actions 仍被设置引用，暂时保留，阶段 02 另建业务输入资产。

## 3. 手动创建目录

在 Project 窗口 Assets 下创建 Moba，再建立：

```text
Assets/Moba/
  Runtime/Core/
  Runtime/Presentation/
  Runtime/Bootstrap/
  Editor/
  Tests/EditMode/
  Tests/PlayMode/
  Tests/Fixtures/
  Scenes/
  Prefabs/
  Config/
  Input/
  Materials/
```

空目录可以先存在。AI、Networking、Replay、Diagnostics 随后续阶段增加。Docs 和 Tools 位于项目根目录，不放进 Assets；文档不需要 Unity 的 .meta。

## 4. 建立 Core 程序集

在 `Runtime/Core` 中创建 Assembly Definition，命名 `Moba.Core`。选中后检查 No Engine References；或把文件内容设为以下**完整 JSON**：

```json
{
  "name": "Moba.Core",
  "rootNamespace": "Moba.Core",
  "references": [],
  "autoReferenced": true,
  "noEngineReferences": true
}
```

这样 Core 中误写 `using UnityEngine;` 会导致编译错误，能够尽早发现层次混用。命名空间不会自动创建程序集边界，真正起作用的是 .asmdef。字段含义见 [Unity 6.3 程序集格式说明](https://docs.unity3d.com/6000.3/Documentation/Manual/assembly-definition-file-format.html)。

不要把 .asmdef 放在整个 Runtime 根目录再重复创建多层混合引用。每个模块自己的文件夹就是边界。

## 5. 建立测试程序集

在 `Tests/EditMode` 创建 `Moba.Tests.EditMode.asmdef`，内容：

```json
{
  "name": "Moba.Tests.EditMode",
  "references": ["Moba.Core"],
  "includePlatforms": ["Editor"],
  "optionalUnityReferences": ["TestAssemblies"],
  "autoReferenced": false
}
```

在 `Tests/PlayMode` 创建 `Moba.Tests.PlayMode.asmdef`：

```json
{
  "name": "Moba.Tests.PlayMode",
  "references": ["Moba.Core"],
  "optionalUnityReferences": ["TestAssemblies"],
  "autoReferenced": false
}
```

打开 Window → General → Test Runner，确认两个分类可见。尚无测试时为空是正常的；阶段 01 会添加真正检验整数移动的测试。不用 `Assert.IsTrue(true)` 充当功能验证。

后续测试引用哪个模块，就在相应测试 asmdef 的 References 中增加哪个模块；不要提前引用不存在的 Moba.AI 或 Moba.Replay。

阶段 02—05 使用新增学习脚本 `ManualLocalBootstrap` 驱动单个世界；阶段 08 用 `DemoBootstrap` 接管正式网络生命周期，禁用旧本地驱动。两个入口绝不能同时对一个世界 Step。

教程中的代码标记规则：

- **完整文件**：可按给出的路径创建该文件；同名类型只保留一份。
- **方法片段**：放入文中指定的已有类，检查说明中的字段和依赖，不能另存为独立脚本。
- **伪代码**：表示调用顺序、算法和待实现接口，不宣称可以直接编译。
- 原项目源码链接是逐方法对照材料；当前完整源码已经包含后期功能，不能把未到阶段的引用一起搬入模板。

## 9. 常见问题

| 现象                          | 检查顺序                                                              |
| ----------------------------- | --------------------------------------------------------------------- |
| 脚本在 IDE 没报错，Unity 报错 | 以 Unity Console 为准，检查 asmdef 引用与程序集位置                   |
| 找不到 NUnit                  | 测试是否放在测试 asmdef 管理的目录，是否启用 TestAssemblies           |
| Core 找不到 UnityEngine       | 这是预期边界；把 Unity 相关代码移到 Presentation/Bootstrap            |
| Scene 中材质粉色              | 检查 Shader 是否使用 Universal Render Pipeline，不要通过禁用 URP 解决 |
| 引用一个尚不存在的程序集      | 删除该提前引用，等对应阶段建立后再加                                  |
