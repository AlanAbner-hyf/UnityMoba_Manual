# 10　英雄跟随相机

[上一阶段](09-回放诊断与故障处理.md) · [返回实现大纲](手动实现大纲.md) · [下一阶段](11-准备房间与连续多局.md)

适用：Unity 6000.3.23f1 / UnityMOBA_Manual。以下是后续手动实施步骤，本次仅写教程文档。

## 本阶段要得到什么

蓝红双方分别跟随自己的英雄，镜头让各自的进攻方向朝屏幕右上；死亡时停留，复活后立即重新定位。选择机器人调试不会切换控制或跟随对象。

前置条件：阶段 08 多进程对局可运行，阶段 09 已明确HUD区域。本阶段只修改 Presentation 与客户端绑定，不改 Core、协议或回放规则。

## 1. 分清三个 ID

| ID | 来源 | 用途 |
| --- | --- | --- |
| ControlledId | 服务端Welcome中的玩家身份 | 鼠标命令控制谁 |
| FollowedId | 本地玩家身份，或离线回放的观察设定 | 镜头跟谁 |
| SelectedId | 鼠标左键选中对象 | HUD显示谁的调试信息 |

网络客户端进入战斗时把 ControlledId/FollowedId设为slot+1。SelectedId可以改变，另外两个保持不变。回放模式可以选定跟随ID，但不产生玩家命令。

## 2. 先把相机旋转计算清楚

采用正交相机，默认 Pitch=55°、ViewSize=12、FollowTime=0.1秒。蓝方Yaw=45°，红方Yaw=225°；相机位于中心减去朝向向量40单位处：

```csharp
// HeroFollowCamera.UpdateCamera中的方法片段
Quaternion rotation = Quaternion.Euler(
    Pitch, FollowedTeam == Team.Blue ? 45 : 225, 0);
BattleCamera.transform.SetPositionAndRotation(
    Center - rotation * Vector3.forward * 40, rotation);
```

地图蓝方推进方向是+X，红方是-X。不要通过旋转地图或反转玩家输入实现双方视角，因为那会影响逻辑/拾取关系。

## 3. 给 BattleView 增加接入点

在阶段02的 BattleView中增加：

```csharp
// BattleView成员片段
public HeroFollowCamera FollowCamera;
public static Rect ViewportFor(int width, int height)
{
    if (width <= 0 || height <= 0) return new Rect(0, 0, 1, 1);
    float sidebar = Mathf.Min(300f, width * 0.4f);
    float left = sidebar / width;
    return new Rect(left, 0, 1 - left, 1);
}
```

这是假设HUD占左侧最多300px的教学布局；把阶段09的HUD绘制区域同步成这个布局。若你采用不同布局，用同一个计算函数统一相机和输入区域。

保持原有Logical和TryGetEntityView方法。Refresh中每次view.Snapshot(entity)后调用`FollowCamera?.Observe(entity)`。切换世界或回房时调用ResetFollow。

## 4. 创建完整 HeroFollowCamera

在 Presentation 创建以下**完整文件**：

```csharp
using System;
using Moba.Core;
using UnityEngine;

namespace Moba.Presentation
{
    public sealed class HeroFollowCamera : MonoBehaviour
    {
        public BattleView View;
        public Camera BattleCamera;
        [Range(35, 75)] public float Pitch = 55;
        [Range(8, 20)] public float ViewSize = 12;
        [Range(0.02f, 0.30f)] public float FollowTime = 0.10f;
        public uint FollowedId { get; private set; }
        public Team FollowedTeam { get; private set; }
        public Vector3 Center { get; private set; }
        public bool HoldingDead { get; private set; }
        private bool observed, wasAlive, snapPending;
        private Vector3 snapPosition;

        private void Start()
        {
            if (View == null || BattleCamera == null) throw new InvalidOperationException("HeroFollowCamera references missing.");
            SanitizeParameters();
        }
        private void OnValidate() => SanitizeParameters();
        private static float FiniteRange(float value, float fallback, float min, float max) =>
            float.IsNaN(value) || float.IsInfinity(value) ? fallback : Mathf.Clamp(value, min, max);
        private void SanitizeParameters()
        {
            Pitch = FiniteRange(Pitch, 55, 35, 75);
            ViewSize = FiniteRange(ViewSize, 12, 8, 20);
            FollowTime = FiniteRange(FollowTime, 0.1f, 0.02f, 0.3f);
        }
        public void BindTarget(uint id, Team team)
        {
            if (FollowedId == id && FollowedTeam == team) return;
            ResetFollow(); FollowedId = id; FollowedTeam = team;
            if (View != null && View.TryGetEntityView(id, out var target)) Observe(target.Entity);
        }
        public void ResetFollow()
        {
            FollowedId = 0; FollowedTeam = Team.Blue; Center = Vector3.zero;
            observed = wasAlive = snapPending = HoldingDead = false;
        }
        public void Observe(EntityState entity)
        {
            if (entity == null || FollowedId == 0 || entity.EntityId != FollowedId) return;
            // Store values: EntityState is mutable and cannot represent a previous snapshot.
            if (entity.Alive && (!observed || !wasAlive))
            { snapPosition = BattleView.Logical(entity.Position); snapPending = true; }
            HoldingDead = !entity.Alive;
            if (HoldingDead) snapPending = false;
            wasAlive = entity.Alive; observed = true;
        }
        private void LateUpdate() => UpdateCamera(Time.unscaledDeltaTime);
        public void UpdateCamera(float deltaTime)
        {
            if (BattleCamera == null || View == null) return;
            SanitizeParameters();
            if (FollowedId != 0)
            {
                if (View.TryGetEntityView(FollowedId, out var target))
                {
                    if (!observed) Observe(target.Entity);
                    if (snapPending) { Center = snapPosition; snapPending = false; }
                    else if (!HoldingDead)
                    {
                        float dt = float.IsNaN(deltaTime) || float.IsInfinity(deltaTime) ? 0 : Mathf.Max(0, deltaTime);
                        Vector3 foot = target.transform.position; foot.y = 0;
                        Center = Vector3.Lerp(Center, foot, 1 - Mathf.Exp(-dt / FollowTime));
                    }
                }
                else { observed = false; snapPending = false; }
            }
            BattleCamera.rect = BattleView.ViewportFor(Screen.width, Screen.height);
            BattleCamera.orthographic = true; BattleCamera.orthographicSize = ViewSize;
            BattleCamera.nearClipPlane = 0.1f; BattleCamera.farClipPlane = 200;
            Quaternion rotation = Quaternion.Euler(Pitch, FollowedTeam == Team.Blue ? 45 : 225, 0);
            BattleCamera.transform.SetPositionAndRotation(Center - rotation * Vector3.forward * 40, rotation);
        }
    }
}
```

分三次理解和验证：

1. BindTarget/ResetFollow管理身份，不能从SelectedId自动推断。
2. Observe只记录值，使用独立wasAlive判断死亡→复活；不能把上帧EntityState引用当快照。
3. LateUpdate在单位显示更新之后平滑中心，再更新Camera位置和朝向。

平滑系数为`1-exp(-dt/FollowTime)`，使不同渲染帧率的跟随速度接近。这里只影响画面，不能写回EntityState。

## 5. 在 Prefab 中绑定

1. 打开ClientPresentation.prefab。
2. 根对象增加HeroFollowCamera；View绑定同根BattleView，BattleCamera绑定BattleCamera子对象。
3. 在BattleView.FollowCamera槽绑定该组件。
4. 相机保持Orthographic，移除旧的自动旋转或跟随脚本，避免两个脚本同时写Transform。
5. 地图下增加CameraBackground，位置(0,-0.6,0)，Scale=(200,0.1,200)，移除Collider，使用背景材质。
6. 保存Prefab，确认场景引用的是修改后的资产。

## 6. 在正确时机绑定玩家

DemoBootstrap收到客户端MatchCreated并创建/绑定世界后：

```csharp
// 方法片段：view和client由Bootstrap持有
uint heroId = (uint)(client.Slot + 1);
view.FollowCamera.BindTarget(heroId,
    client.Slot == 0 ? Team.Blue : Team.Red);
```

不要在Welcome之前绑定默认slot=0；也不要在每次Refresh里反复ResetFollow，否则相机会每帧跳动。

切换回放时先ResetFollow，再按回放配置选定蓝方或红方英雄。退出回放/回房再次清理。

## 7. 死亡与复活的处理顺序

- 存活时跟随EntityView显示位置，允许插值与平滑。
- Observe检测到死亡后HoldingDead=true，镜头保持当时的中心，不跟随隐藏或尸体对象继续平滑。
- false→true复活时记录新的整数出生点换算坐标，下一次UpdateCamera直接snap到该点。
- 下局重新绑定清空observed/wasAlive，不让上一局的死亡状态污染新局。

阶段14保留尸体后仍用这套Alive状态判断，不能因尸体GameObject可见就误当英雄存活。

## 8. 编写相机测试

PlayMode测试程序集引用Moba.Presentation。用测试构造的BattleView与Camera调用BindTarget、Observe、UpdateCamera，避免依赖人工帧率。

| 检查 | 操作 | 断言 |
| --- | --- | --- |
| 蓝方进攻方向 | 将中心与中心+X投影到viewport | 后者x、y均更大 |
| 红方进攻方向 | 将中心与中心-X投影 | 后者x、y均更大 |
| 选择独立 | 修改SelectedId为机器人 | FollowedId不变 |
| 死亡停留 | Observe死亡，反复UpdateCamera | Center不再变化 |
| 复活跳转 | Observe新出生存活状态 | Center直接到出生点 |
| 时间无效值 | 传负数或NaN dt | 不产生NaN Transform |
| 参数越界 | 非法Pitch/Size/FollowTime | 被限制到允许范围 |
| hash隔离 | 更新相机前后计算StateHasher | hash相同 |

参考测试：[HeroFollowCameraTests.cs](../../UnityMOBA/Assets/Moba/Tests/PlayMode/HeroFollowCameraTests.cs)。

## 9. 两客户端人工检查

同时打开两客户端，分别移动、死亡、复活，调整窗口宽高比，左键选机器人。检查相机背景没有突然露空，右键拾取没有因viewport缩小而偏移。

如果camera jitter，先确认显示对象Render与Camera.LateUpdate的顺序。两者都在LateUpdate时可把BattleView渲染安排在Update或通过Script Execution Order明确先视图后相机；不要靠偶然脚本顺序。
