## 本阶段要得到什么

先不接 Socket，在一个 EditMode 测试里创建服务端、客户端一、客户端二三份独立世界。相同帧指令执行 6000 帧，每一帧 SHA-256 相同；缺一方输入时无法生成帧。

前置条件：阶段 04 的状态和配置已经稳定；阶段 05 的 AI 输出可以作为指令记录。注意“同进程一致”只是联网前的验证，不代替实际多进程与跨平台测试。

## 2. 写配置的唯一编码

创建以下**完整文件** `Core/BattleConfigCodec.cs`。这是阶段 04 配置的编码，没有 Collision 字段。


```csharp
using System.IO;

namespace Moba.Core
{
    // One fixed-order encoding is shared by the handshake, replay header and configuration hash.
    public static class BattleConfigCodec
    {
        public static void Write(BinaryWriter w, BattleConfig c)
        {
            w.Write(c.ConfigVersion); w.Write(c.MinX); w.Write(c.MaxX); w.Write(c.MinZ); w.Write(c.MaxZ);
            w.Write(c.HeroSpeed); w.Write(c.HeroHp); w.Write(c.TowerHp); w.Write((byte)c.Mode);
            w.Write(c.HeroDamage); w.Write(c.HeroRange); w.Write(c.HeroWindup); w.Write(c.HeroCooldown);
            w.Write(c.SkillRadius); w.Write(c.SkillDamage); w.Write(c.SkillCooldown); w.Write(c.RespawnDelay);
            c.Lane.Write(w);
        }

        public static BattleConfig Read(BinaryReader r) => new BattleConfig(
            r.ReadInt32(), r.ReadInt32(), r.ReadInt32(), r.ReadInt32(), r.ReadInt32(),
            r.ReadInt32(), r.ReadInt32(), r.ReadInt32(), (SimulationMode)r.ReadByte(),
            r.ReadInt32(), r.ReadInt32(), r.ReadInt32(), r.ReadInt32(),
            r.ReadInt32(), r.ReadInt32(), r.ReadInt32(), r.ReadInt32(), LaneConfig.Read(r));
    }
}
```


Read 的位置参数严格匹配 BattleConfig 构造器。自己增加一个配置字段时，必须同步更新构造、Write、Read 和配置哈希测试，不能只在网络 Hello 中补一个值。

验证方式：配置写到 MemoryStream，再读回来，对所有字段比较；同时试试非法模式、负数生命和截断数据。流长度校验还会在协议层加强。

## 3. 实现规范化状态写入

创建 `Core/CanonicalStateWriter.cs`：


```csharp
// 完整文件：Assets/Moba/Runtime/Core/CanonicalStateWriter.cs
using System;
using System.IO;
using System.Linq;
using System.Text;

namespace Moba.Core
{
    public static class CanonicalStateWriter
    {
        public const int SchemaVersion = 4;

        public static byte[] Write(WorldState state)
        {
            if (state == null) throw new ArgumentNullException(nameof(state));
            using (var stream = new MemoryStream())
            using (var writer = new BinaryWriter(stream, Encoding.UTF8, true))
            {
                writer.Write(0x53544154u); writer.Write(SchemaVersion);
                writer.Write(state.Frame); writer.Write((byte)state.Result);
                writer.Write(state.NextEntityId); writer.Write(state.RandomState);
                writer.Write(state.NextWaveFrame); writer.Write(state.WaveNumber);
                var entities = state.Entities.OrderBy(e => e.EntityId).ToArray();
                writer.Write(entities.Length);
                uint previous = 0;
                foreach (var entity in entities)
                {
                    if (entity.EntityId <= previous) throw new InvalidOperationException("Duplicate or zero entity ID.");
                    previous = entity.EntityId;
                    writer.Write(entity.EntityId); writer.Write((byte)entity.Kind); writer.Write((byte)entity.Team);
                    writer.Write((byte)(entity.Alive ? 1 : 0)); WritePoint(writer, entity.Position);
                    writer.Write(entity.Hp); writer.Write((byte)entity.State); WriteCommand(writer, entity.Intent);
                    writer.Write(entity.AttackReadyFrame); writer.Write(entity.HitFrame); writer.Write(entity.SkillReadyFrame);
                    writer.Write(entity.RespawnFrame); writer.Write(entity.LastDamagedFrame);
                    writer.Write(entity.PathIndex);
                }
                writer.Flush(); return stream.ToArray();
            }
        }

        public static byte[] WriteConfig(BattleConfig config)
        {
            if (config == null) throw new ArgumentNullException(nameof(config));
            using (var stream = new MemoryStream())
            using (var writer = new BinaryWriter(stream, Encoding.UTF8, true))
            {
                writer.Write(0x434F4E46u); writer.Write(SchemaVersion); writer.Write(BattleConfig.RulesVersion);
                writer.Write(BattleConfig.LogicHz); BattleConfigCodec.Write(writer, config);
                WritePoint(writer, config.BlueSpawn); WritePoint(writer, config.RedSpawn);
                WritePoint(writer, config.BlueTower); WritePoint(writer, config.RedTower);
                WritePoint(writer, config.Lane.Midpoint);
                writer.Flush(); return stream.ToArray();
            }
        }

        public static void WritePoint(BinaryWriter writer, Int2 point) { writer.Write(point.X); writer.Write(point.Z); }
        public static void WriteCommand(BinaryWriter writer, CombatCommand command)
        { writer.Write((byte)command.Kind); WritePoint(writer, command.Point); writer.Write(command.TargetId); }
    }
}
```


本阶段沿用这一字段布局。SchemaVersion 数字是布局版本，不表示中间版已经兼容参考项目；RulesVersion 仍使用自己的 manual-lane-1。

必须覆盖的字段可以这样检查：

| 字段组 | 为什么不能漏 |
| --- | --- |
| Frame、Result | 决定下一帧与是否继续 |
| NextEntityId、RandomState | 决定未来创建/随机分支 |
| NextWaveFrame、WaveNumber | 当前画面一样也可能下一波不同 |
| 实体 ID、Kind、Team、位置、HP | 身份与当前战斗状态 |
| Intent、State、HitFrame | 下一帧可能继续移动或命中 |
| AttackReadyFrame、SkillReadyFrame | 下一次行为是否合法 |
| RespawnFrame、LastDamagedFrame、PathIndex | 复活、回复和兵线路径 |

实体先按 ID 排序；字符串/整数格式固定，不用 JSON 的默认属性顺序当作规范化协议。GetHashCode 不保证跨进程稳定，不可用作同步哈希。

## 4. 计算 SHA-256

创建 `Core/StateHasher.cs`：


```csharp
// 完整文件：Assets/Moba/Runtime/Core/StateHasher.cs
using System;
using System.Security.Cryptography;

namespace Moba.Core
{
    public static class StateHasher
    {
        public const int HashSize = 32;
        public static byte[] Compute(WorldState state) => Hash(CanonicalStateWriter.Write(state));
        public static byte[] ConfigHash(BattleConfig config) => Hash(CanonicalStateWriter.WriteConfig(config));
        public static byte[] Hash(byte[] canonicalBytes)
        { using (var sha = SHA256.Create()) return sha.ComputeHash(canonicalBytes); }
        public static string Hex(byte[] hash) => BitConverter.ToString(hash).Replace("-", "").ToLowerInvariant();
        public static bool Equal(byte[] a, byte[] b)
        {
            if (a == null || b == null || a.Length != HashSize || b.Length != HashSize) return false;
            int difference = 0;
            for (int i = 0; i < HashSize; i++) difference |= a[i] ^ b[i];
            return difference == 0;
        }
    }
}
```


SHA-256 在这里检查状态是否相同，不是证明客户端可信的反作弊签名。客户端和服务器自己分别计算，然后比较同一个帧号。

## 5. 输入窗口只解决“是否齐全”

创建 `Networking/InputWindow.cs`：


```csharp
// 完整文件：Assets/Moba/Runtime/Networking/InputWindow.cs
using System;
using System.Collections.Generic;
using System.IO;
using Moba.Core;

namespace Moba.Networking
{
    public enum InputAcceptance { Accepted, Duplicate, Stale }
    public sealed class InputWindow
    {
        public const int Width = 3;
        private readonly Dictionary<int, CombatCommand>[] pending = { new Dictionary<int, CombatCommand>(), new Dictionary<int, CombatCommand>() };
        private readonly BattleConfig config;
        public InputWindow(BattleConfig config) { this.config = config ?? throw new ArgumentNullException(nameof(config)); }
        public InputAcceptance Add(int slot, int frame, int serverFrame, CombatCommand command)
        {
            if (slot < 0 || slot > 1) throw new InvalidDataException("Invalid player slot.");
            if (frame < 1) throw new InvalidDataException("Invalid input frame.");
            command.Validate(config);
            if (frame <= serverFrame) return InputAcceptance.Stale;
            if ((long)frame > (long)serverFrame + Width) throw new InvalidDataException("Input beyond window.");
            if (pending[slot].TryGetValue(frame, out var existing))
            {
                if (!existing.Equals(command)) throw new InvalidDataException("Conflicting duplicate input.");
                return InputAcceptance.Duplicate;
            }
            pending[slot].Add(frame, command); return InputAcceptance.Accepted;
        }
        public bool Has(int slot, int frame) => pending[slot].ContainsKey(frame);
        public bool TryTake(int frame, out FrameCommands commands)
        {
            commands = null;
            if (!pending[0].TryGetValue(frame, out var blue) || !pending[1].TryGetValue(frame, out var red)) return false;
            commands = new FrameCommands(frame, blue, red);
            pending[0].Remove(frame); pending[1].Remove(frame); return true;
        }
    }
}
```


逐条验证：

- slot 为 0/1，由连接归属决定，不让消息自报任意槽位。
- frame ≤ serverFrame 是过期输入。
- 只接受未来 3 帧以内的输入，防止无界缓存。
- 同槽同帧同内容视为重复；同槽同帧不同内容拒绝。
- TryTake 必须有双方输入才成功；只有成功后才删除缓存。

frame n 一方没点击，要提交 NoOp。未收到该方输入则继续缺输入，不能替他生成 NoOp。

## 6. 墙钟调度与战斗计时分开

创建 `Networking/FrameScheduler.cs`：


```csharp
// 完整文件：Assets/Moba/Runtime/Networking/FrameScheduler.cs
using System;

namespace Moba.Networking
{
    // Wall-clock scheduling only. CombatWorld never reads this clock.
    public sealed class FrameScheduler
    {
        private readonly double period;
        public double NextDue { get; private set; }
        public FrameScheduler(int frequency)
        { if (frequency < 1) throw new ArgumentOutOfRangeException(nameof(frequency)); period = 1.0 / frequency; }
        public void Start(double now) => NextDue = now + period;
        public bool IsDue(double now) => now >= NextDue;
        public void Advanced(double now, bool resumedFromInputWait)
        {
            // Preserve the healthy cadence across render-frame quantization. After waiting or
            // a whole missed period, reset the deadline instead of replaying wall-clock debt.
            NextDue = resumedFromInputWait || now - NextDue >= period ? now + period : NextDue + period;
        }
    }
}
```


now 来自 Stopwatch 等单调时间，仅用于“是否轮到尝试下一帧”和网络超时；CombatWorld 永远不读取这个 now。

网络等待 2 秒后不要一次跑 40 个猜测帧。恢复时用 `Advanced(now, true)` 重新排下一个时间点，保留帧指令完整性。

## 7. 三份世界测试

创建 `Tests/EditMode/StateHashTests.cs`。以下是**完整示例测试类**，使用 MovementFixture 避免自然胜负提前结束：

```csharp
using Moba.Core;
using Moba.Networking;
using NUnit.Framework;

public sealed class StateHashTests
{
    [Test]
    public void ThreeIndependentWorldsAgreeFor6000Frames()
    {
        var config = new BattleConfig();
        var server = CombatWorld.Create(config);
        var first = CombatWorld.Create(config);
        var second = CombatWorld.Create(config);
        var inputs = new InputWindow(config);
        for (int f = 1; f <= 6000; f++)
        {
            var command = f % 200 == 1
                ? CombatCommand.MoveTo(new Int2(f % 400 == 1 ? -30000 : 30000, 2000))
                : CombatCommand.NoOp;
            inputs.Add(0, f, server.State.Frame, command);
            Assert.That(inputs.TryTake(f, out _), Is.False);
            inputs.Add(1, f, server.State.Frame, CombatCommand.NoOp);
            Assert.That(inputs.TryTake(f, out var frame), Is.True);
            server.Step(frame);
            first.Step(frame);
            second.Step(frame);
            var expected = StateHasher.Compute(server.State);
            CollectionAssert.AreEqual(expected, StateHasher.Compute(first.State), "first frame " + f);
            CollectionAssert.AreEqual(expected, StateHasher.Compute(second.State), "second frame " + f);
        }
    }

    [Test]
    public void FutureCooldownChangesHash()
    {
        var a = CombatWorld.Create(new BattleConfig());
        var b = CombatWorld.Create(new BattleConfig());
        b.FindEntity(1).SkillReadyFrame = 100;
        Assert.That(StateHasher.Equal(
            StateHasher.Compute(a.State), StateHasher.Compute(b.State)), Is.False);
    }
}
```

随后增加集合重排测试：规范化顺序相同则 hash 相同。测试可以在 Core 测试友元中构造 WorldState，不能把排序后的新状态写回正在运行的世界来掩盖顺序错误。

## 8. 把 AI 指令加入统一帧

在测试或学习驱动中按下面**伪代码**组织：

```text
如果调度时间未到：返回
n = serverWorld.Frame + 1
如果 InputWindow.TryTake(n) 失败：
    标记等待；不 Step；不 Evaluate AI；返回
robots = serverAi.Evaluate(n)
frame = FrameCommands(n, blueInput, redInput, robots)
服务端 Step(frame)
把 frame 交给两个独立客户端，各自 Step(frame)
分别保存 n 的 canonical bytes 和 hash
检查三份 hash
更新 FrameScheduler；若从等待恢复则重置下一期限
```

只有服务端有 ServerAiSystem；客户端重放 frame.Robots。不要让三端各自执行行为树，哪怕本机测试“碰巧一样”。

这里可以用测试中的 Queue<FrameCommands>模拟三端传递。它是教学夹具，不是网络传输，也不会天然模拟乱序或丢包；这些属于下一阶段。

## 9. 建立失败定位步骤

检测差异时保留：帧号、配置哈希、双方哈希、该帧命令、最近几帧规范化字节。先对比最早不一致帧的字段，不先盯住最终位置。

手工注入一次 `SkillReadyFrame += 1`，证明系统能在画面看起来相同的情况下检测差异。不要只验证 Position 改动。

## 10. 常见问题与验收

| 现象 | 排查 |
| --- | --- |
| 三世界总是一样却测试无意义 | 是否误用了同一个 CombatWorld 引用 |
| 显示时间改变后 hash 变 | 将 UI/插值/墙钟字段写入了状态编码 |
| 客户端总慢一帧 | 比较的是 S(n) 与 S(n-1) |
| 卡住但没人操作 | 客户端未发送 NoOp |
| 6000 帧用 Match 模式提前结束 | 换 MovementFixture 或明确较短完整对局测试，不在结算后继续 Step |
