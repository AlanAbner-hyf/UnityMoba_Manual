# 14　英雄死亡动画与尸体停留

[上一阶段](13-KayKit模型与动画.md) · [返回实现大纲](手动实现大纲.md) · [下一阶段](15-跨平台构建与完整验收.md)

适用：Unity 6000.3.23f1 / UnityMOBA_Manual。本文是后续实施与验证教程；本次未进行构建、部署或运行游戏。

## 本阶段要得到什么

玩家Knight和机器人Barbarian死亡时播放Death_A，结束后保持倒地姿态并停留在死亡地点；复活时恢复同一个显示对象。尸体不能被拾取，不阻挡逻辑移动。

前置条件：阶段13的UnitVisual能按逻辑显示时间播放动作；阶段12的碰撞已经排除死亡单位。本章修改表现，不改伤害、复活时间、协议或回放格式。

## 1. 明确三种“死亡”

| 层次 | 行为 |
| --- | --- |
| Core | HP=0、FSM=Dead、记录RespawnFrame、禁止行动、碰撞排除 |
| EntityView | 保留英雄显示对象，关闭血条/阵营环/拾取Collider，锁定死亡地点 |
| UnitVisual | Death优先，采样非循环剪辑，停在末帧 |

保留尸体不意味着给世界增加一具新实体。英雄仍使用原EntityId；小兵由Core死亡移除，塔沿用已有表现。

## 2. 为两种英雄绑定Death_A

1. 用阶段13的派生动画流程从General组取Death_A，保存到Animations/KayKit/Death_A.anim。
2. 确认Loop Time关闭、Animation Events为空，根位移/旋转曲线已处理。
3. 打开HeroView和RobotHeroView的UnitVisualProfile，将Death拖入对应槽。
4. MinionView.Death保持空，本章不实现小兵尸体。
5. 在Inspector检查两个英雄Prefab都引用正确Profile，Animator开启对象存在，applyRootMotion=false、fireEvents=false。

不要只在场景实例上临时拖引用；保存Prefab/配置资产，重新打开场景核对。

## 3. 检查阶段13已经加入的Death时间逻辑

如果按阶段13完整UnitVisual实现，下面行为已经具备，现在逐项检查而不是复制第二份代码：

- Pose优先级第一项为`!alive ? UnitPose.Death`。
- 从存活变为死亡时记录一次deathStart，清attackEnd和castEnd。
- 后续死状态快照不刷新deathStart。
- 首次创建显示对象就是死状态时，也能记录起始时间并进入Death。
- Death采样时间clamp到[0, clip.length]，不取模循环。
- 已死亡时OnSimEvent忽略普攻/技能表现请求。

关键**方法片段**位于Snapshot：

```csharp
if (!entity.Alive && (!wasDead || reset))
{
    deathStart = System.Math.Max(0, nextFrame - 1) / (double)BattleConfig.LogicHz;
    attackEnd = castEnd = -100;
}
```

这里nextFrame是本次已收到的逻辑帧，变量名不表示可以猜测未来状态。之后Sample使用同一(n-1+alpha)/20时间轴。

## 4. 替换EntityView的隐藏逻辑

阶段02在死亡时直接隐藏Body，这会导致死亡动画看不到。阶段12又扩展了Motion路径插值；本章把两者统一为下面的**完整EntityView文件**：

```csharp
using Moba.Core;
using UnityEngine;
namespace Moba.Presentation
{
    public sealed class EntityView : MonoBehaviour
    {
        public uint EntityId { get; private set; }
        public EntityState Entity { get; private set; }
        public Renderer Body;
        public BattleView Owner;
        public UnitVisual Visual;
        public Transform LabelAnchor;
        private readonly Vector3[] path = new Vector3[11];
        private int pathCount;
        private float elapsed, pathLength;
        private bool initialized, wasAlive;
        private Vector3 deathPosition;
        private MaterialPropertyBlock colors;
        private Collider[] pickers;
        public static Color TeamColor(Team team) => team == Team.Blue ? new Color(.12f, .72f, 1) : new Color(1, .27f, .38f);
        private void Awake() { pickers = GetComponentsInChildren<Collider>(true); }
        public void SetSnapshot(EntityState entity, int frame = 0, float radius = .55f)
        {
            Entity = entity; EntityId = entity.EntityId;
            Vector3 destination = BattleView.Logical(entity.Position);
            bool snap = !initialized || (!wasAlive && entity.Alive);
            bool corpse = !entity.Alive && entity.IsHero && Visual && Visual.Profile && Visual.Profile.Death;
            if (corpse)
            {
                if (!initialized || wasAlive) deathPosition = destination;
                destination = deathPosition;
            }
            pathCount = 1; path[0] = destination; pathLength = 0;
            if (!snap && !corpse && entity.Motion.Count > 1 && entity.Motion[entity.Motion.Count - 1] == entity.Position)
            {
                pathCount = entity.Motion.Count;
                for (int i = 0; i < pathCount; i++)
                { path[i] = BattleView.Logical(entity.Motion[i]); if (i > 0) pathLength += Vector3.Distance(path[i - 1], path[i]); }
            }
            transform.position = path[0]; wasAlive = entity.Alive; initialized = true; elapsed = 0;
            gameObject.SetActive(entity.Alive || corpse || entity.Kind == EntityKind.Tower);
            if (Visual) Visual.Snapshot(entity, frame, pathLength, snap, Owner && Owner.SelectedId == EntityId, radius);
            if (Body != null)
            {
                if (colors == null) colors = new MaterialPropertyBlock();
                Color c = entity.Alive ? TeamColor(entity.Team) : new Color(.2f, .22f, .25f);
                colors.SetColor("_BaseColor", c); colors.SetColor("_Color", c); Body.SetPropertyBlock(colors);
            }
            if (pickers == null) pickers = GetComponentsInChildren<Collider>(true);
            foreach (var collider in pickers) collider.enabled = entity.Alive;
        }
        public void RenderAt(float fraction)
        {
            if (pathCount == 0) return;
            fraction = Mathf.Clamp01(fraction); float distance = pathLength * fraction; Vector3 direction = Vector3.zero;
            transform.position = path[pathCount - 1];
            for (int i = 1; i < pathCount; i++)
            {
                Vector3 delta = path[i] - path[i - 1]; float length = delta.magnitude;
                if (length > 0) direction = delta / length;
                if (distance <= length && length > 0) { transform.position = Vector3.Lerp(path[i - 1], path[i], distance / length); break; }
                distance -= length;
            }
            if (Visual) Visual.Sample(fraction, direction);
        }
        public void AdvancePresentation(float delta)
        {
            if (Owner != null && Owner.PresentationPaused) return;
            elapsed = Mathf.Min(1f / BattleConfig.LogicHz, elapsed + delta * (Owner != null ? Owner.PlaybackSpeed : 1));
            RenderAt(elapsed * BattleConfig.LogicHz);
        }
    }
}
```

依赖说明：UnitVisual来自阶段13，MotionTrace来自阶段12，BattleView需有Logical、SelectedId、PresentationPaused和PlaybackSpeed。原字段Body在KayKit英雄上可以为空，实际蒙皮交给Visual；塔仍使用Body。

关键行为是`gameObject.SetActive(entity.Alive || corpse || entity.Kind == EntityKind.Tower)`。如果上层BattleView仍对所有!Alive直接Destroy，必须移除那条规则；只销毁已从World.Entities移除的实体或整局清理。

## 5. 更新BattleView的所有调用点

把旧Snapshot/Render调用统一替换：

1. Instantiate EntityView后赋`view.Owner = this`。
2. 新逻辑帧调用`view.SetSnapshot(entity, world.State.Frame, world.Radius(entity)*0.001f)`。
3. LateUpdate对激活视图调用`view.AdvancePresentation(Time.unscaledDeltaTime)`。
4. 删除旧的BattleView全局age加上EntityView.elapsed同时更新的代码，保留一条表现时钟路径。
5. 继续只在新逻辑帧转发SimEvent，保持HeroFollowCamera.Observe(entity)。
6. HUD血条绘制加`entity.Alive`判断；尸体不显示血条。
7. 清理整局时Destroy全部EntityView并清字典；UnitVisual会释放PlayableGraph。

检查点：活着时移动和攻击仍正常，死亡后对象active=true但Collider.enabled=false，且HP条和Marker隐藏。

## 6. 尸体位置为何单独保存

参考代码首次发现corpse时把逻辑死亡位置复制到deathPosition；后续死状态快照继续使用该值。即使显示快照被重复刷新，也不能把尸体拉到出生点。

复活由Core的Alive变化决定。`snap = !initialized || (!wasAlive && entity.Alive)`令路径只保留新出生点，Visual.ResetState清掉deathStart，恢复Idle。

每次Snapshot要先读取旧wasAlive，再更新它。反过来先赋值会丢失死亡/复活边沿。

## 7. 先验证一个角色完整生命周期

在独立PlayMode测试世界中：

1. 记录英雄站立的脚底、髋骨高度、蒙皮包围盒和ActiveGraphs。
2. 通过测试友元设置HP=0、State=Dead、未来RespawnFrame，推进下一帧并刷新显示。
3. 采样死亡开始、中段、结尾，记录姿态。
4. 死亡动画长度之后继续推进若干帧，最终姿态应保持不变。
5. 推进到复活帧，确认对象仍是同一个实例、位置在合法出生点、姿态恢复、Collider和Marker打开。
6. 第二次杀死该英雄，确认从新的deathStart重新倒地。
7. 结束/回房，等待一帧后图数量归零。

用测试设置死亡时不要只设State不设HP；Alive基于HP。实际玩法则仍由ResolveDamage进入Dead，不能在生产代码中绕开。

## 8. 验证冻结与抢占边界

| 场景 | 应观察到的行为 |
| --- | --- |
| 攻击前摇中死亡 | 立即转Death，后续AttackStarted不抢回 |
| 施法动作中死亡 | Death优先 |
| 连续多个死亡快照 | 不反复播放开头 |
| 回放暂停 | 骨骼与蒙皮不继续变化 |
| 1×播放0.02秒与2×播放0.01秒 | 相同显示时间处姿态相同 |
| 网络长时间等待 | 最多推进到已知帧末，然后停住 |
| 从已死亡快照首次创建 | 显示尸体，不永久隐藏 |
| 复活点拥堵 | 逻辑未复活则继续尸体，不用本地计时自行站起 |

## 9. 验证真实网格，不只检查动画状态名

只断言Pose==Death不能证明玩家看到了倒地。使用SkinnedMeshRenderer.BakeMesh获取当前实际顶点包围盒，与站立姿态比较；阈值按模型站立高度归一化，不用一个绝对骨骼高度套所有模型。

测试截图若在同一编辑器帧多次同步Camera.Render，可能复用GPU蒙皮缓存。可等待真实帧或用当前采样姿态BakeMesh辅助截图，再在真实客户端独立检查，不能只凭陈旧截图判断动画失效。

参考：[DeathVisualTests](../../UnityMOBA/Assets/Moba/Tests/PlayMode/DeathVisualTests.cs)、[死亡表现说明](../../UnityMOBA/Docs/DeathVisuals.md)。

## 10. 回归验证和常见问题

用同一个旧碰撞规则回放验证hash仍逐帧相同；本次只是表现变化，不应要求重录战斗才能“通过”。同时两客户端观察同一英雄死亡位置与最终姿态，再连续两局检查图释放。

| 现象 | 常见原因 |
| --- | --- |
| 死后瞬间消失 | 仍有Body隐藏/SetActive(false)/上层Destroy路径 |
| 死亡开头一直抽动 | 每帧重置deathStart |
| 尸体仍能被右键攻击 | 拾取Collider未关闭，或输入未检查Alive |
| 复活后还是躺着 | 未检测false→true或ResetState未清死亡时间 |
| 第二次死亡不播放 | deathStart只在整个对象生命周期设一次 |
| 回房后图数量不归零 | 对象未Destroy或图释放漏分支 |
